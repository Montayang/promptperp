# 投资人账本会计政策 v2（schema v4）

状态：共享池迁移与多池数据模型基线
日期：2026-09-27

本文冻结 C0 会计语义。修改任何一项都需要新 migration、兼容性说明和验收证据，不能只改代码默认值。

## 计价与精度

- 本位币和首版唯一支持资产为 `USDT`；非 USDT 手续费或资金流直接阻断，不能猜测汇率。
- 货币金额最多 8 位小数，份额和单位净值最多 18 位小数，全部使用 `Decimal`。
- 申购份额向下取整，赎回份额向上取整；精度残差留在策略池，不归操作员或单个投资人。
- 池权益按 8 位金额精度确认；投资人展示权益也按 8 位金额精度确认。

## 复式分录

每个业务事务至少有两条分录且借贷相等。首版科目包括：策略池现金、投资人投入资本、投资人提款、策略已实现损益、手续费和资金费。

- 入金：借记策略池现金，贷记投资人投入资本。
- 出金：借记投资人提款，贷记策略池现金。
- 正收益/正资金费：借记策略池现金，贷记对应收益。
- 亏损/负资金费：借记对应收益，贷记策略池现金。
- 手续费：借记手续费，贷记策略池现金。

已实现损益、手续费和资金费必须来自能够证明 `strategy_id/run_id/intent_id/order_id/trade_id` 所有权的确认事件。钱包余额变化只用于对账，不能直接产生收益分录。

## 份额和回报

首个投资人按初始单位净值 `1 USDT` 申购。之后的申购和赎回使用最近一次已通过对账的单位净值：

```text
issued_units = contribution / unit_nav
redeemed_units = withdrawal / unit_nav
investor_equity = investor_units * unit_nav
cumulative_return =
  (equity + cumulative_withdrawals - cumulative_contributions)
  / cumulative_contributions
```

投资人与策略池是多对多关系；每个 `(investor_id, pool_id)` 独立保存份额、累计申购和累计赎回。改变策略比例必须在允许资金流的窗口中按池赎回和申购，不能改写旧份额记录。多池组合报表尚未启用时，系统必须明确阻断，不能静默选择其中一个池。

既有业务迁入时使用一次性的 opening migration：历史净入金形成投资人资本，切账权益与历史净入金之差形成显式迁移前累计损益。操作员确认过的旧月报单独保存为 `imported_investor_snapshots`，不得伪装成已经与交易所核验的正式估值快照。

## 资金流门禁

入金、出金和策略切换必须提供非空的 operator、reason 和 external reference，并同时满足：

- 无受管或外来持仓；
- 无普通、条件或保护订单；
- 无待结算事件或未知执行结果；
- 无超过 `0.00000001 USDT` 的未解释差额；
- 最近一次成功对账不超过 15 分钟，且时间不在未来；资金流携带的 reconciliation ID 和时间必须与用于申赎定价的估值快照完全一致。

资金转账本身造成的预期账户差额必须由上层操作流程在过账前核验；本模块不监听币安充值，也不自动认领未声明资金。

## 对账与估值

每次估值输入必须恰好覆盖全部活动策略池。内部权益为池现金与明确提供的未实现损益之和。交易所权益与内部权益差异超过 `0.00000001 USDT`，或存在任何外来/未知对象时，对账状态为 `BLOCKED`，不得发布新估值快照。

报表和邮件查询只读取最近一次已通过对账的不可变快照，并显示截止时间和 reconciliation ID。缓存值不得称为实时余额。月报可配置每月 1 至 28 日的本地发送日和发送时间；报告周期使用相邻两个发送日作为边界。

## 更正、保留和费用

- 已提交分录不可更新或删除；发现错误时使用带原因和关联 ID 的冲正及重记事务。首版尚未开放通用人工调整入口。
- 总账、source event、对账和估值长期保留；邮箱可以停用但不能通过改写历史记录移除。
- 管理费、业绩报酬、高水位线和税务不在 v1 范围，系统不会隐式计算。
- 账本文件、WAL、备份、导出、收件去重库和报告均为敏感运行状态，禁止提交 Git。
