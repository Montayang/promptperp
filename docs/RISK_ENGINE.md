# 操作员风险引擎

A4 风险引擎位于策略与执行状态机之间。策略只能提出意图和交易上下文，不能修改政策，也不能直接调用 `ExecutionCoordinator.submit_entry` 绕过风险决定。

## 不可变政策

`RiskPolicy` 是冻结、版本化配置，包含稳定指纹。第一版覆盖：

- 市场、标的、方向和订单类型 allowlist；
- 单笔最大保证金、名义价值和杠杆；
- 最大同时仓位数和可用余额缓冲；
- 强制止损、止损方向和单笔最大允许损失；
- 行情最大年龄和计划价格最大偏离；
- 时间窗口订单数和连续失败阈值；
- 日内亏损上限；
- `NORMAL`、`REDUCE_ONLY` 和 `KILL_SWITCH` 模式。

策略得到的是只读政策对象。任何政策版本或字段变化都会改变指纹，运行批准必须重新绑定。

## 决策流程

每个 `RiskRequest` 同时包含交易意图、操作类型和由受信运行时提供的账户/行情上下文。风险引擎收集所有拒绝原因，而不是只返回第一个错误。

健康状态具有最高优先级。以下任一情况对开仓和减仓均为阻断错误：

- 订单结果未知；
- 对账失败；
- 保护不完整；
- 检测到外来订单或仓位。

OPEN 必须通过全部 allowlist、敞口、余额、止损、行情、频率、失败和日损检查。`REDUCE_ONLY` 或 `KILL_SWITCH` 禁止 OPEN。

REDUCE 在降级模式下仍可使用，但必须证明仓位属于当前 run，减仓量不得大于已证明的自有数量。未知账户状态下不能以“紧急”为由修改仓位。

## 执行层门禁

`ExecutionCoordinator.submit_entry(intent, authorization)` 的授权参数不可省略。执行层在任何事件写入和交易网关调用前验证：

- 决定明确允许；
- 动作为 OPEN；
- strategy/run/intent 与交易意图完全一致；
- 包含非空风险政策指纹。

拒绝产生 `RiskRejected`。A5 受支持策略运行时只会传入 `RiskEngine` 生成的决定。

## 审计

每次 evaluate 无论允许或拒绝都写入 `RiskAuditSink`。结构化决定包含政策 ID、版本、指纹、意图所有权、动作、稳定原因码、时间和必要的市场上下文。

审计上下文不包含 API Key、Secret、SMTP 密码、完整余额或不必要账户响应。生产持久化审计接收器在 A6 接入，当前内存接收器用于确定性离线测试。
