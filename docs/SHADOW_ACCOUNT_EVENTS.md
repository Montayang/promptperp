# 币安真实事件影子接入

状态：只读采集、归属验证与显式批准的投资人总账过账已实现
日期：2026-09-28

## 目的与边界

下游执行器必须为 entry、stop、take-profit 和主动 exit 生成确定性的 Binance client ID，
并在请求发出前把 `strategy_id/run_id/intent_id` 写入独立 SQLite 归属表。成交结束后，影子
同步器只读调用 USD-M `Account Trade List`、`Get Income History`、订单查询和条件单历史接口。

该链路本身不下单、不撤单、不发送邮件，也不修改策略的滚仓金额。默认只把已经验证归属的事件保存为 `VERIFIED_PENDING_LEDGER`；只有运行器显式使用 `--post-investor-ledger` 时才过账到投资人总账。测试中的 `user0 = 1500 USDT` 不会进入生产数据库。

## 归属规则

- 普通订单以提交前持久化的 client order ID 为根，响应中的 exchange order ID 为直接证据；请求结果不确定时可通过 client ID 只读恢复 exchange order ID。
- 条件保护单同时保存 client algo ID 和 algo ID；触发后必须从条件单历史取得 `actualOrderId`，再与逐笔成交的 `orderId` 匹配。
- 每个 fill 使用 `symbol + tradeId` 作为稳定事件 ID。一个市价单拆成多个 fill 时逐条处理，手续费和已实现损益不会被订单级合并遗漏。
- 资金费使用 `tranId`，且发生时间必须唯一落入同 symbol 的受管持仓区间。
- 非 USDT 手续费、未知订单、区间不唯一的资金费和内容冲突事件进入 `QUARANTINED`，不得猜测归属。

## 捕获边界与恢复

首次启用采集时在 `shadow_metadata.capture_started_at` 写入不可变边界。首次启用总账过账时另写入 `ledger_posting_started_at`；边界前的成交不会补记，若当时存在旧的 `VERIFIED_PENDING_LEDGER` 事件则拒绝晋级。重启只重扫相关边界之后、最多最近七天的数据；数据库的事件 ID 唯一约束保证重扫幂等。每次受管仓位结算后还会扫描从开仓前一分钟到平仓后一分钟的窗口。

启用过账后，每次启动和每笔平仓同步后都会读取交易所总权益，以全部活动策略池、零未实现盈亏执行对账。只有差额为零且生成完整估值快照时才允许继续；投资人权益通过既有份额乘以新单位净值自然分配，不改写历史份额。

账户预检必须先确认空仓且无挂单，运行器才会创建或迁移影子数据库。恢复读取失败、归属关闭失败、同步失败或出现任何 `QUARANTINED` 事件都会把运行器置为阻断状态；已经发生的平仓结算不会被伪造回滚，但系统不会继续开启下一笔交易。

生产路径必须位于 Git 忽略、仅服务身份可写的状态目录。主文件、WAL 和导出均属于敏感
账户运行状态，不得提交、打印或通过邮件发送。

## 总账过账条件

只有满足以下条件后，才能通过 `--post-investor-ledger` 开启：

1. 操作员审核真实投资人、初始权益和策略池映射；
2. 启动时空仓、无挂单且交易所权益与正式账本完全一致；
3. 对账、备份恢复、监控告警和停机手册完成生产验收；
4. 操作员单独批准账本影响资金分配。
