# 共享账户执行与权益报告

**简体中文** | [English](SHARED_EXECUTION.md)

这些库组件用于在交易所合并持仓的情况下区分策略归属，不包含实盘运行器、交易策略，
也不提供账户物理隔离。零基础快速上手仍然只运行离线示例。

## 组件能力

- `VirtualPositionStore` 记录策略和运行批次的持仓数量、成本、已实现盈亏、手续费及
  资金费。Decimal 运算和持久化事件身份支持确定性重放，小数形式的零数量也视为空仓。
- `VirtualFillRouteRegistry` 将客户端订单绑定到唯一归属，并按合约和交易所订单 ID
  索引已确认订单；归属不唯一的查询会被拒绝。
- `VirtualFillRecovery` 在应用一批成交前先核实全部归属；未知成交会阻断恢复，
  不会被随意分配给某个策略。
- `BasketPolicy` 和 `preflight_basket` 检查平衡组合、数量舍入、最小数量及名义价值。
  持仓数量和目标权重必须由调用方明确提供，包内没有生产组合默认参数。
- `BasketExecutionStateMachine`、执行协调器和回退管理器持久化先减仓后加仓、
  订单不确定、部分成交及仅针对所属仓位的回退。不能假定中断的组合已成交或未成交。
- `SharedAccountTurn` 将配合使用它的本机运行器串行化。`SharedAccountBusy` 表示尚未
  取得锁，可以延后轮询，但不得推进信号或下单。未解决执行标记和对账失败是不同错误，
  必须继续阻断。

现有平台独占合约的分配规则不变，安装本次更新不会自动启用重叠持仓。下游运行器必须
明确接入归属投影、交易所真实状态核对、共享锁、审批及崩溃恢复后，才可考虑实盘使用。
文件锁仅协调同一主机，不支持分布式运行器。

运行 `python examples/offline_shared_execution.py` 可查看虚构四仓组合的预检示例。
它不创建交易所客户端，输出 `execution_permitted: false`。其中数字只是测试输入，
不是组合配置建议。

## 交易所读取与错误处理

`BinanceAccountSnapshotReader` 通过注入的交易所客户端读取仓位、余额、持仓模式、
普通挂单和条件挂单。`BinanceAccountEventReader.list_fills` 提供带时间戳的标准化
成交。这些是账户私有读取接口，不是离线演示。

`read_api_permissions` 读取权限标志；默认网络访问需要通过运行模式、副作用及审批
门禁，测试只注入假客户端。`require_restricted_futures_scope` 要求读取、合约交易和
IP 限制开启，提现和划转关闭。它不会修改 API 权限，账户身份和模式仍需集成方核实。

只有少数明确未执行的拒单会被视为确定失败。未知错误、超时以及带有成交量的拒绝响应
仍视为结果不确定，必须先核对，不能盲目重发。

## 权益记录与定时汇总

`reporting.equity_history.EquityHistory` 接收调用方提供的、已核对的策略估值，每个
UTC 分钟保存一个样本到仅所有者可访问的 SQLite 文件。必须明确提供正的初始权益和
部署身份，可配置时区和每日汇总小时。重开同一部署时不能悄悄改变已保存的报告规则。

`summary(start, end)` 计算样本区间盈亏、启动以来收益和样本最大回撤；
`html(start, end)` 返回离线 HTML/SVG 权益曲线。起止时间必须带时区，报告会披露实际
样本覆盖范围，超过两分钟的缺口不连线。所有样本必须采用一致估值口径。此版本假定
同一部署期间无出入金，不是现金流调整后的基金绩效引擎，也不代表投资者资金池净值。

`daily(now, notify)` 在配置的当地小时之后、存在新鲜样本时调用明确提供的发送回调。
它没有内置 SMTP 客户端或后台调度器，应在交易执行关键路径之外调用。发送前先持久化
领取记录；发送不确定或进程崩溃需要人工复核，不自动重发。这避免盲目重复发送，但
不保证严格只送达一次。报告数据和生成报告均不得提交到 Git。

## 迁移与安全检查

已有单笔执行与投资者账本 API 不变。新集成使用新的虚拟持仓和订单路由数据库；本次
不提供旧数据库自动迁移、已有仓位自动接管或账户模式自动更改。有持仓时应保留原运行器，
另行审阅归属状态迁移，不能删除状态重新开始。

集成前运行 `./scripts/quality.sh`。新增测试只使用虚构数据和假交易所客户端，测试
通过不授予实盘权限。共享记账不能隔离交易所强平、保证金、故障和人工账户操作的风险。
