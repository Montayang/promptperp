# C5 邮件 outbox 投递验收

状态：PASS；生产定时器模板已完成但未启用
日期：2026-10-01

## 已实现

- schema v4 为邮件增加 `SENDING`、delivery ID 和领取时间；
- 只有账本中仍为 verified 的收件地址可以领取；
- 领取和 attempt 递增在同一事务完成，并发或重复领取失败关闭；
- SMTP 使用 STARTTLS，发件地址和密码只从 owner-only 环境文件读取；
- 收件地址只来自已领取的 outbox，不接受命令行覆盖；
- 真实发送要求干净提交、匹配 commit 和最长一小时批准窗口；
- SMTP 或落库结果不确定时保留 `SENDING`，禁止自动重试；
- dry-run 只报告待发送数量，不连接 SMTP。
- scheduler 依据账本内 daily/weekly/monthly 偏好生成到期报表并持久化下一到期点；
- 定时投递每次只领取最早一封邮件，使用确定性 delivery ID 和独占租约；
- 未对账、未来或超过 15 分钟的估值不会生成“当前净值”报告；
- 邮件 worker 拒绝含 Binance 交易配置的环境文件。

## 验收证据

- fake SMTP 验证 STARTTLS、登录、目标地址、主题和退出顺序；
- 成功投递只增加一次 attempt 并进入 `SENT`；
- 模拟超时后保持 `SENDING`，不会回到自动重试队列；
- v3 数据原位升级到 v4，账本和历史 outbox 保持可读；
- 全量质量门禁必须在真实 smoke test 之前通过。

## 生产边界

本入口一次最多发送一个明确 message ID 或 `--next` 选中的最早待发送消息。它不启动
策略、不访问币安，也不会在同次调用批量发送。真实地址、邮件正文、投递状态和凭据都
属于本地敏感运行数据，不得提交 Git。systemd 模板只是部署材料；真实定时发送仍需
操作员提供最长一小时的独立批准窗口并显式启用 timer。
